## 怎麼使用

### 內容類型

| 類型 | 貼到哪裡 |
|---|---|
| **CLI Command** | VS Code 下方的 **Terminal**，按 Enter 執行 |
| **Bash Script** | 同樣貼到 Terminal，會自動寫成 `.sh` 檔 |
| **Python Script**、**設定檔**、**Markdown 片段** | 用編輯器開啟指定的檔案，整段貼上並**存檔**（不是貼到 Terminal） |

每一題的格式都一樣：**標題 → 說明表格 → 複製貼上的區塊**。先讀說明，再複製區塊；GitHub 上每個區塊右上角都有複製按鈕。

### 四條貼上規則

1. **一次只貼一個區塊**，看完輸出再貼下一個。
2. 看到 ⚠️ **貼上前請替換**，要先把 `<...>` 換成你自己的內容，`<` `>` 符號也要刪掉。
3. 看到 🔒 **單獨執行**，代表這個指令需要你輸入內容，**不可以和其他指令一起貼上**。
4. 注意每一題標示在哪一台機器執行；第 9 章會同時用到【開發機】與【部署機】兩台 codespace。

### 符號說明

| 符號 | 意思 |
|---|---|
| ⚠️ | 容易出錯、務必注意的地方 |
| 🔒 | 需要互動輸入，必須單獨貼上 |
| ℹ️ | 補充說明，例如「這個警告是正常的」 |
| 📝 | 請記下來，後面的步驟會用到 |
| ✅ | 驗收：完成這一段後應達成的狀態 |

## 遇到問題時

- 先看該題下方的 ⚠️ 提示，大多數常見錯誤都有寫處理方式。
- 第 9 章的部署腳本失敗時會以 `❌` 說明原因，對照第 9 章「G. 部署失敗時」的錯誤訊息表。
- 不確定 Git 現在的狀態，就執行 `git status`；其他救命指令在第 6 章「F. 救命指令」。
